# Agent Host integration, RC2

Agent 0.11.4 exports additive `agentHostV1` alongside unchanged `cockpitV1` and protected `nativeTransportV1`. Provider-kit 1.1.3 exports `AgentHostAdapter`, its DTOs and the reviewed local transport. PM consumes this interface; it does not parse AHP. Microsoft’s official TypeScript client is pinned to `@microsoft/agent-host-protocol` 1.0.0. Standard WebSocket framing uses `ws` 8.21.3.

The client offers protocol 1.0.0 and 0.9.0. Exact installed Stable 1.141.0 source accepts 0.9.0; Insiders 1.142.0 source accepts 1.0.0/0.9.0. The live negotiated version remains UNKNOWN until an authorized connection initializes. Availability of an installed implementation does not prove a running host, usable account, model or native completion.

## Reviewed workflow

PM prepares an immutable ordinary DEFAULT task from Config and Jul, including exact prompt, role, root, Git revision, source authority and Config policy hashes. Agent independently verifies the actual Git root/revision and its reviewed PM local or GitHub/GitLab repository identity. Local identity is accepted only without a supported remote identity. A separate source review grants this exact scope.

`reviewHostConnection` asks for one exact, explicitly selected documented `agent-host/local-endpoint/entries/<identity>.json` entry in the intended approved profile. BEFORE reading its contents, Agent asks separately for access to its sensitive bearer credential and that local connection. It validates schema 2, canonical filename, PID liveness, version syntax, regular file/no links, and the published named pipe/socket or standalone loopback TCP address. Tokens are held only in an Agent closure; they never reach PM, storage, diagnostics, logs or evidence. Entry changes deny reconnect. An editor endpoint and standalone endpoint are different authorities. No host is started, default registry guessed, unrelated session scanned, authentication supplied or provider account substituted.

Agent initializes the official client and inspects actual provider/model inventory. Unsupported model/effort, protocol changes and provider capability changes block submission. Native PLAN/GOAL semantics remain unqualified and are refused. Effective engine/model/effort remain UNKNOWN: an echoed request selection is not independent provider evidence. The transport does not change native permissions or account settings.

Both exact installed native Codex and Claude sources use `model.config.thinkingLevel`. Requested effort is accepted only when the uniquely selected model advertises that exact string property with an explicit enum wholly inside the provider's recognized list (Codex: none/minimal/low/medium/high/xhigh/max/ultra; Claude: low/medium/high/xhigh/max). Missing, malformed, duplicate, readonly or extra enum values block effort mapping. No arbitrary enum or permission field is copied. A null effort uses the native default; observed effective effort remains UNKNOWN. Exact source receipts: [Claude model configuration](https://github.com/microsoft/vscode/blob/ff00e788322523ee1e9e8ee2c9bb4b89af93a3c2/src/vs/platform/agentHost/common/claudeModelConfig.ts) SHA256 `2c9e92c9b110a8be624dea1b7002cfa23c5bffc485665284ff412d8d481564b5` (identical Stable); [Insiders Codex agent](https://github.com/microsoft/vscode/blob/ff00e788322523ee1e9e8ee2c9bb4b89af93a3c2/src/vs/platform/agentHost/node/codex/codexAgent.ts) SHA256 `69e7c7b8e65221f5c4ece240ad8a8ae5e26799a124cc42b06a713ddb0e82aa30`; [Stable Codex agent](https://github.com/microsoft/vscode/blob/2a59476c9bfcb90b3ddc372c36762471b7dfad1c/src/vs/platform/agentHost/node/codex/codexAgent.ts) SHA256 `3fab92bd2aee16a0dca7aa0535f7579f77dc38c890f72f35fb5ab58739749752`.

Preparation persists an opaque owned handle before PM can dispatch. Task approval binds the complete preparation hash, task, prompt, host, provider and protocol, followed by Agent’s exact-task modal. A durable create intent precedes `createSession`; a durable send intent precedes exactly one `chat/turnStarted`. Session and turn URIs at this point are explicitly client assigned, not provider discoveries. Observed host session provider/root and default chat must agree before sending. No dependent task, queued continuation, uncertain retry or automatic native permission approval is implemented.

Root/session/chat reducers and protocol framing are Microsoft's SDK. Only this adapter’s owned session/chat is subscribed; session catalog ownership is never inferred from titles, paths or times. The response preview includes bounded redacted markdown only; tools, thinking, credential-bearing metadata and other turns are excluded. Permission/input-required, authentication-required, failed, cancelled/stopped, completed and uncertain states remain distinct. Completion does not accept the PM task.

Recovery requires renewed source permission and the same reviewed host identity, protocol and provider inventory. It subscribes to authoritative snapshots for the persisted session/chat/turn and validates the exact prompt. It never creates another session or resends. Host disappearance retains UNCERTAIN. `agent.revokeAgentHostConnections` drops local source/connection grants and observations; it does not silently cancel native work. Owned cancellation can request native acknowledgement. No public same-session Agents Window reveal command is qualified, so `reveal` returns UNAVAILABLE; PM retains the existing native Open/Copy fallback.

## Qualification scope

The deterministic `test/agentHostFixture.ts` host uses the official in-memory transport, typed protocol messages and official reducers. It is labelled SYNTHETIC and is excluded from extension/provider-kit runtime exports. Tests cover both offered compatible versions, inventory, exact approval, session creation, one prompt, streaming/redaction/completion, durable replay/reopen without resends, changed source/root/revision, task/prompt/role policies, native permissions/auth, stale/malformed endpoint metadata, host disappearance, multiple hosts, identity ambiguity and changed protocol/capabilities. A separate owned synthetic WebSocket named-pipe fixture tests the actual standard framing and private synthetic bearer boundary. An inert Git fixture verifies real local/remote repository alias mapping.

These tests do not run Codex or Claude, read a real endpoint credential, authenticate a provider or qualify installed GUI isolation. Live response/recovery, provider-specific installed support and independent GUI qualification remain separate BLOCKED/UNKNOWN gates. The protected direct-spawn transport, platform verification and Ed25519 checks are unchanged.
