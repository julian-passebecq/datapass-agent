# Optional installed PM and Agent journey

The existing `release-qualification` workflow accepts optional `pm_sha`: the exact lowercase 40-character PM commit bound to the approved Windows CI artifact in `test/fixtures/installed-pm`. Its receipt binds source SHA, package SHA256, prior successful Windows CI run and the 107 PM acceptance IDs with their source CSV hashes. The existing smoke installs that actual PM VSIX and the current Agent VSIX into one isolated profile on the hosted Windows runner. The PM test fixture is excluded from the Agent product package. Local PM GUI execution is refused; no owner desktop, authentication or provider execution is used.

Attempt 1, run `38178586140` at Agent `d6c92675049f8a97d60644c40de2a4cc633fe370`, failed before GUI because the workflow token could not check out the private PM repository. No GUI success is attributed to it. Reusing the already approved exact-source CI artifact requires no new credentials or account changes.

`scripts/smoke-pm-agent.mjs` extends that same Electron extension host. Visible PM controls import generated reviewed definitions, configure the generated Git repository, connect its task authority, create and edit a task, select Kanban, prepare an immutable campaign, read reviewed Agent sessions and Git evidence, search approved sources, and open the selected task in Agent. Agent's actual initial metadata and rendered context strip are checked against persisted task bytes, task revision, observed session and Git SHA. The actual Return button must produce PM's positive return notice and preserve the original task/page/view.

Negative journeys change only generated fixture state: invalid return token through the actual public PM command, changed Git SHA, missing provider source, revoked reviewed scope and extension-host reload. A fresh source review and handoff must reconnect after reload. None of these checks substitutes caller metadata for source authority.

A fixed runner-only observer extension reads public installed Agent exports and PM state. It never replaces product or VS Code APIs, intercepts transport, creates grants or invokes a positive return. Its invalid-token command deliberately invokes the actual PM handler. Observer assertions are recorded separately from GUI actions. Generated untitled previews are copied into allowlisted QA files before navigation, reload and shutdown; no personal document is opened or read.

The inherited smoke's `--disable-workspace-trust` launch flag applies only to this generated runner workspace. It does not qualify production trust approval. Config-owned native preset preparation, real authenticated provider actions and account/security dialogs remain explicit dependency or human authentication gates. The module does not install or alter Config, Lens or Brain.

The optional journey writes `.smoke/pm-agent-result.json`, generated screenshots and retained generated preview files. It records actual Electron/extension-host PIDs, VS Code version, installed product IDs/versions, source and package hashes, fixture Git revision, runner identity and the sanitized public observer snapshot. GUI and observer checks remain separate. Deeper Agent actions exercise realistic Codex/Claude transcripts, filters, native worker/workflow links, provenance, selected markdown and scoped incremental export. Duplicate-tool assertions deliberately retain failure evidence before any runtime correction. PM exercises actual narrow and wide windows, both themes, editable fields, keyboard navigation, Delivery and an exact-SHA CI read with whatever availability the real source reports. A failed action writes its available evidence and fails the existing smoke. Results remain PENDING until an exact-head hosted run completes; static syntax and fixture preparation are not installed GUI qualification.
