# Agent-owned native transport v1

Agent 0.11.2 exports `nativeTransportV1` (major 1, version 1.0.2). The additive provider-kit 1.1.2 owns the same implementations and emitted TypeScript contracts. Configuration capture retains its schema and inert collector. Existing cockpitV1, observer, exporter and all 47 screens remain independent.

PM calls the installed Agent API, never a caller-supplied runtime module or copied parser. `preflight(request, selection)` checks a reviewed exact regular executable SHA256, explicit home/cwd, capability inventory and startup effect receipt. Preflight performs no CLI probe or native task. `prepare(request, input)` binds exact text, targetHash, permissionHash, configHash, presetHash, promptHash, bindingHash, Agent scopeHash and independent configScopeHash, native selection and optional owned resume source into preparedHash. scopeHash is Agent `digest(request.scope)`; configScopeHash comes from Config role binding and is never inferred equal. An empty project uses `reviewProjectScope({organizationId,privacyDomainId,projectId,repoId,root,revision,sourceVectorHash,policyHash})`: hardened Git validates exact root/canonical origin/HEAD before and after local review. Agent returns a separate execution Scope/epoch with empty sessionKeys, no manufactured observation, and no observer/config/export consent. A freshly reviewed Git revision update retains the canonical scope hash and advances only that project’s epoch; approving another project does not revoke unrelated work.

`review(request, preparedHash)` displays an Agent-owned exact task/modal for native execution authority. An observer grant alone never creates this authority. `start(request, {taskId,preparedHash})` consumes that review, validates executable/preflight again and commits an exclusive durable spawn intent in Agent globalStorage before spawning. PM can poll `lookup`, subscribe to safe native progress/message projections and request `cancel` on its own task. Start never retries. Duplicate task IDs, stale epochs, changed scopes/hashes and uncertain startup are refused. A crash/reload converts in-flight observations to UNCERTAIN. workspace-write acquires durable leases on proven canonical remote identity and real Git common metadata in Agent’s shared ledger. Owned writers across the same cwd, linked worktrees and same-origin clones cannot overlap. Proven native settled outcome releases leases; uncertainty and process-only cancellation retain them. No absence of external writers is inferred. A resume requires a newly reviewed task and a ledger-owned completed/interrupted session with proven native quiescence and unchanged target, permission, selection and Config/role bindings. Its new exact promptHash is reviewed independently and never overwrites the prior prompt receipt; a session lease prevents overlapping resumes.

Fixed transports are Codex app-server (stdio JSONL), Codex exec JSONL and Claude Code print stream-json. Every prompt uses stdin or JSON-RPC text input with shell:false; no arbitrary shell API, argv override, eval, automatic goal or cognitive loop is exposed. Codex app-server initializes before thread/start or thread/resume and turn/start; turn/completed is matched to the owned session/turn. Codex/Claude CLI success requires both native completion and zero process exit. Failure, cancellation request, missing/malformed final event and uncertain spawn stay distinct. Cancellation affects only the child owned by this host instance; unknown/reloaded processes are never searched or killed. Codex cancellation uses turn/interrupt when its owned turn is known.

Native approval, permission and MCP/security requests are refused for handling in the native interface. Ordinary follow-up text uses a separately reviewed resume task; it never becomes a permission grant. Requested model/effort/account are kept separate from provider-reported observations. Unknown observed identity stays null. Native result text is bounded and redacted through Agent's existing redaction layer; reasoning, tool payloads, auth and raw stderr never cross the facade. Delta events carry progress only until a complete assistant text item can be redacted safely; split credential fragments cannot escape through raw deltas. A native result is NATIVE_REPORTED, never independent acceptance, a CI verdict or a Git commit assertion.

`getRoleRuntime({bindingHash,scopeHash})` (the Config producer scope hash) returns only a matching owned ledger association in a currently reviewed scope. It returns RUNNING or STOPPED with nativeSessionId, nativeReceiptRef (canonical receipt hash) and observedAt; absent, stale, uncertain, unproven quiescence or revoked association is UNKNOWN. It never infers NOT_STARTED from an empty observer/catalogue. This supports Config's guarded role switch checkpoint checks without a second runtime/parser.

Startup effects must be audited **before launching any native executable**, including an apparently harmless capability probe. The host must independently verify isolated execution, exact binary/version/help support, managed/user/project config, hooks, MCP processes, plugins/instructions, auth home ownership and repository trust. Caller declarations do not constitute OS isolation or account verification. NativeSelection's reviewed capability/effect receipt is included in the exact local approval; the implementation cannot certify an arbitrary receipt. Claude uses `--restricted`, exact tools, `--permission-mode default` and strict MCP flags. No `--allowedTools` or permission auto-approval is supplied. The default projection has only read or read/edit file tools; Bash/testing/Agent/subagent capability is not implied. An explicitly reviewed Config reference to native-name mapping can retain Read/Glob/Grep/Edit/Write/Bash/Agent/Task inside an independently certified descendant boundary, with a signed toolPolicyHash; permission requests stay native/manual and the print CLI has no verified human-response round trip. Managed policy still applies. No settings, credentials, trust state or owner desktop are changed by this API. Empty synthetic homes and fake process protocol fixtures qualify transport logic only. Actual accounts, installed native versions and isolated GUI journeys remain separate gates.

Official protocol/startup references reviewed 2026-10-12:

- [Codex app-server protocol](https://learn.chatgpt.com/docs/app-server): initialization, thread/turn lifecycle, streams, interruption, approval and MCP requests.
- [Codex CLI reference](https://learn.chatgpt.com/docs/cli/reference): exec JSONL, exact session resume, sandbox/config overrides; authentication remains provider owned.
- [Claude Code CLI reference](https://code.claude.com/docs/en/cli-reference): print/stream JSON, resume, restricted mode, tool restrictions and strict MCP config.
- [Claude Code hooks](https://code.claude.com/docs/en/hooks): SessionStart can execute during start/resume, before the first task response.
- [Claude Code programmatic usage](https://code.claude.com/docs/en/headless): system/session, assistant and result stream records.

Only flags verified in the installed capability receipt are usable. Published online documentation does not prove an older installed native version supports them. This implementation does not claim live native account or host qualification.

Startup safety correction 0.11.1: call installed captureStartup(request,selection), preview its exact manifest/configurationHash/reviewHash and verification, then bind the returned manifest into the prepared selection. Missing or drifted local files, opaque customization/inherited/system sources, untrusted/expired platform proof and incomplete ambient/managed/isolation coverage refuse native creation. Source/schema details and the independent verifier trust boundary are in [NATIVE-STARTUP-PROOF.md](NATIVE-STARTUP-PROOF.md). Installed/exact bytes, configured local manifest, trusted verifier reports, authentication and working tool/task evidence are separate; the latter two remain UNKNOWN before native evidence.

Version 1.0.2 separates the isolated user `home` from optional explicit `providerHome`. HOME/USERPROFILE keep the former; CODEX_HOME/CLAUDE_CONFIG_DIR and the startup inventory use the latter. Omitted providerHome preserves legacy direct-home semantics. The exact environment and manifest remain bound by the independent platform proof; no home is auto-discovered. Codex uses the file credential backend in that selected provider home, matching isolated owner login without an OS credential-store fallback. PM must require 1.0.2 before sending a separate providerHome.

Owned Codex app-server messages stream only complete lines, redacted with the existing shared redaction layer and bounded in UTF-8 bytes. Incomplete token fragments remain private until the authoritative completed message. Message/turn/session identity, item bounds and late completed-item deltas are checked. Final native text retains formatting; a partial streaming reply is still NO_COMPLETION_EVIDENCE. This does not bypass startup proof, native permissions or isolation requirements.
