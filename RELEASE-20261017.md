# Agent 0.11.9 private qualification candidate

This candidate fixes the concrete incremental-export defect observed in installed job 80 on preserved Agent 0.11.8 (`e72d0c4312746e1ff7012126bb9fd2c0fdd8f9fc`). That run correctly previewed a rewritten source after truncation, but the length-only execution guard refused the fresh approved shorter snapshot. Job 80 remains FAILED; its thirteen completed UI requests are partial evidence only.

A changed capture now binds its prior cursor contents and immutable manifest into the reviewed plan hash. Execution compares that predecessor under the existing destination lock. A fresh truncation may therefore commit a shorter curated full-session resnapshot, while a stale plan still refuses after a concurrent append, rewrite or first commit. A truncate/reappend cycle cannot recover an old receipt instead of advancing the current cursor. Unchanged re-plan/repeat remains idempotent. Source hashing, exact local approval, scope revocation, curated redaction, staging, immutable objects and atomic manifest commit remain required. The v1 manifest and object format is unchanged; historical receipts need no migration.
